# 共通の質問形式（dig / grilling 共用）

人間に判断を求める質問は、この形式で出す。情報・事実の取得を本人への質問にしない（調査は AI の仕事）。

## 各質問の構成

- **Q ID**: `Q1`, `Q2`, ... と連番にする
- **短い題 / 決めること**: 何を決めてほしいかを1行で
- **前提・根拠**: 次の3種を混ぜずに分けて書く
  - AI の仮説（推測・提案の根拠）
  - 観測（コード・ドキュメント・環境から確認した事実）
  - 本人発言（過去の回答・発言の引用）
- **具体候補 2〜4個**: 各候補にメリット/デメリット（pros/cons）を添える。抽象的な自由記述だけの問いにしない
- **推奨と理由**: AI の推奨案とその理由を明示する（あくまで提案であり決定ではない）
- **本人選択と本人理由**: 本人が候補を選ぶか自由記述で答えられるようにする。理由は本人の言葉で記録し、候補の説明文を本人の理由として転記しない

## 質問の出し方（利用できる手段をこの順で使う）

1. `request_user_input_async` が使える → それを使う
2. 使えるモードの `request_user_input` がある → それを使う
3. Cursor の AskQuestion ツールがある → それを使う（schema が `id`/`label` だけなら pros/cons を label に埋め込む）
4. どれもなければ通常会話で、番号付きの質問・選択肢・推奨案を提示する

ルール:

- 存在しないツールを前提にしない。使える schema の項目だけを使う
- UI の上限（質問数・選択肢数・文字数）に収まらなければ、独立した問に分割する
- 質問数を埋めるための不要な質問をしない
- 回答を待つ。無回答や事前選択（デフォルト値）を本人の決定として扱わない
- 最終的に合意済みの判断を、あとから再確認しない
- 実際に使った手段を判断記録に書く
