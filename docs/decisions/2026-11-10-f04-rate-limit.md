# 2026-11-10-f04-rate-limit: /api/quests・/api/gemini に IP ごとの回数制限を付ける（F04）

- 日付: 2026-11-10
- 決めた人: AI（superloop の F04 worker、無人実行）。**AI判断・PM確認待ち**
- 根拠: `docs/SPEC.md` の F04「`/api/quests`・`/api/gemini` に IP ごとの回数制限（メモリ内）。超過で 429、`/walk` は見本に切り替えて知らせる。テストあり」
- 関連: `docs/DECISIONS.md` の D-F04、D-008（F03 の失敗の原因）

## コードから観測した事実（実装前）

- `src/app/api/quests/route.ts` と `src/app/api/gemini/route.ts` には回数制限がなく、コメントに「本番では認証・レート制限を付けること」とあった
- `/walk` の失敗は `QuestFailure`（`src/lib/quests.ts`）で原因を分け、`RouteScreen` の知らせに出している（F03）
- 調整ページ `/prompt-lab` は「3件を生成」で `/api/quests` を一度に3回呼ぶ（`src/components/PromptLab.tsx`）

## AI の実装判断（PM 確認待ち）

- 方式: メモリ内の固定窓。理由と他の候補は D-F04
- 上限: 1つの IP につき1分10回、ルートごとに別に数える。`/walk` は1回の体験で1回、`/prompt-lab` は1回で3回呼ぶので、数回のやり直しまで通る値にした。計測に基づく値ではない
- 判定は入力の検証より前に行う（不正な入力の連打も数える。Gemini は呼ばない）
- IP（評価役の差し戻し後に2回変更）: 最初は `X-Forwarded-For` の先頭を使っていたが、利用者がヘッダーを変えるだけで制限を避けられると評価役に指摘された。次に「ロードバランサが末尾に足す CLIENT_IP, LB_IP の右から2番目」に変えたが、stg で実測すると末尾に付くプロキシは2つ（`…, 接続元IP, 35.219.200.69, 66.249.82.x`）で、右から2番目は接続元ではなく共有インフラの IP だった。さらに `x-fah-client-ip` というヘッダーがあり、偽の値（`9.9.9.9`）を送っても前段が実接続元 IP で上書きすることを確認した。外部調査でも「x-fah-client-ip はクライアントの IP を返す（Google サポート確認済み）」と報告されている（https://github.com/arcjet/arcjet-js/issues/5383 ）。よって次のようにした
  - stg・prod（`NEXT_PUBLIC_APP_ENV` が stg / prod）: **`x-fah-client-ip` を接続元にする**。ない・IP の形でないときは共通のキー `unknown` でまとめて数える（制限は外さない）。X-Forwarded-For は使わない（左側は利用者が書け、右側の位置も経路依存で安定しないため）
  - local・未設定など: 前段にプロキシがなく、Next.js はヘッダーがあればそのまま渡す（`node_modules/next/dist/server/base-server.js` の `req.headers['x-forwarded-for'] ??= ...socket.remoteAddress`）ので、ヘッダーは利用者が自由に書ける。**ヘッダーを無視し全員を1つのキー `local` で数える**。ローカルは1人で使う前提
  - `X-Real-IP` は使わない（同じく偽れる）
  - 実測: `evidence/F04/stg-headers.txt`（stg に届いたヘッダーの実値）、`evidence/F04/stg-curl.txt`（別の接続元 IP は別に数えられること、偽装で避けられないこと）
- メモリ: 覚える IP は 10,000 件まで。超えたら期限切れを捨て、それでも多ければ古い順に捨てる
- 429 の応答: `Retry-After`（秒）と `{ error, reason: "rate_limited" }`。サーバーログに `[quests] rate limited` / `[gemini] rate limited` を出す（IP はログに出さない）
- `/walk`: 理由が読めなくても 429 なら `RateLimited` にし、「短い時間にAIを呼びすぎた（1分ほど待つとまた使えます）ため、サンプルのクエストを表示しています（AIが作ったものではありません）」と出す
- 旧 `YorimichiApp`（どのルートからも使われていない）は変えていない

## 未解決

- `x-fah-client-ip` は公式ドキュメントに記載を見つけられていない（実測と外部調査の一致で採用）。将来 App Hosting がこのヘッダーを変えた場合、接続元が取れず全員が共通キー `unknown` に倒れる（制限が厳しくなる側）
- インスタンスが複数になると上限はインスタンス数倍になる（stg は max 1、prod は max 2）
