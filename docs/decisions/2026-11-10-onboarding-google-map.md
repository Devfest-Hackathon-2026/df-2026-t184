## 経緯

本人は `/walk` の案内の1枚目（手描きの地図）を見て、次のように述べた。

> この案内も実際のデータと地図のスクショ使いたいなw

AI は最初、地理院の地図タイルにルートを重ねた静止画を勧めた。本人の返答は次のとおり。

> ほんとはgoogle mapが使用されているので、実際の画面が描画されるようにしたいからgoogle mapの画像がいいのでは？

AI は Google の地図の利用ガイドライン（https://about.google/brand-resource-center/products-and-services/geo-guidelines/ ）を確認した。アプリへの組み込みは「use Google Maps Platform instead」とあり、スクショを静止画としてアプリに置く使い方は、はっきりとは許可されていない。そこで、本体と同じ Google マップを案内の中でその場で表示する案を示した。本人の返答は「おk対応して」。

ローカルで表示を確認したあと、本人の返答は「いい感じじゃん 進めてもらっていいでしょうか？」。

選定理由：本人の理由は上の引用（本体と同じ実際の画面を見せたい）。静止画を採らない理由は AI が示したガイドラインの記述で、本人の理由として補完しない

## 決定

- 案内の1枚目に、本体と同じ Google マップの部品で、上野公園 → 谷中 → 鶯谷の固定ルートを表示する
- 位置情報の許可と地名検索（Geocoding）は使わない。地点は固定する
- キーがない・失敗したときは、これまでの手描きの地図に戻す
- 説明文の「人の多い通りを避けた」は、まだない機能なので書き換える

## 費用

案内を開くたびに、地図の読み込み1回と Routes API の呼び出し2回（最短・寄り道）がかかる。どちらもすでに使っている API で、新しい API やキーは追加しない。
