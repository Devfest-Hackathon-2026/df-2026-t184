# /walk から /terrain へのつなぎ方: ルート画面に別タブのリンクを置く

- 日付: 2026-11-10
- 状態: AI判断・PM確認待ち（superloop の worker が F09 で決めた）
- セッション参照: 未取得（無人ループの worker。人への質問はしていない）
- 質問手段: なし（`docs/RULES.md`「判断に迷う点は人に聞けない。自分で決めて進める」に従った）

## 背景（コードから観測した事実）

- `/walk` は `WalkApp` の中で screen 状態を持つ SPA で、タブ（さがす・アルバム・ハンコ帳・ともだち）もアプリ内切り替え
- `/terrain` は別ページ（`src/app/terrain/page.tsx`）で、対象は上野公園〜谷中〜鶯谷の固定デモ経路。`/walk` の行き先とは無関係
- `/terrain` の「推定値・現地未検証」と出典は従来 `<details>` の中だけで、開かないと見えなかった。「不明区間」は「評価済み区間率」の裏側の表現しかなかった

## 決めたこと

- ルート画面（`RouteScreen`）に `/terrain` へのリンクカードを置き、`target="_blank" rel="noreferrer"` で別タブにする（採用）。歩行中の state はメモリ内なので同タブ遷移だと寄り道の途中記録が消える
- リンクの注記で「固定デモ経路（いまの寄り道ルートとは別）・推定値・現地未検証・不明区間あり」を画面に出す
- `/terrain` 側でも、折りたたみを開かなくても「固定経路・推定値・現地未検証」が見えるよう header に常時表示し、「不明区間（標高）」「不明区間（日陰）」の行を表に足した。`/walk` へ戻るリンクを先頭に置いた
- 候補: (A) ルート画面に別タブリンク（採用）、(B) タブバーに「地形」タブを足す、(C) `/walk` 内に `TerrainCompare` を埋め込む
- 捨てた理由: B はタブがアプリ内画面の切り替えだという一貫性を崩す（外部ページへ飛ぶタブは押した人を混乱させる）。C は比較が固定デモ経路であるのに、いま歩いているルートの比較のように見えてしまい、完了条件の「固定デモ経路であること」を画面で伝えにくい

## 確かめていないこと

- 実機ブラウザでの別タブ遷移の手触りと見た目（jsdom ではリンクの属性と文言のみ確認）
