# 2026-11-10-walk-slope-shade: /walk で坂・日陰の希望を選び、ルート画面に推定値を出す

- 日付: 2026-11-10
- 質問手段: チャットで選択肢を提示（入力で選ぶ＋範囲内は計算 / Elevation API を足す / 表示のアピールだけ）
- 回答: 「入力で選ぶ＋範囲内は計算」、実装は AI が直接行う（PM）
- 本人の要望: 坂道を減らしたい、行き先として日陰のアピールが少ない、行き先が出た後の画面が詰まっている

## 決めたこと

- 入力の最後の質問（寄り道の時間）に「歩きやすさ（任意）」として「坂は少なめがいい」「日陰を通りたい」を置いた。質問の数は増やしていない（既存の流れとテストを崩さないため。AI 判断・PM 確認待ち）
- 選んだ希望は `/api/quests` に `care` として渡し、Gemini のプロンプトに足す。サーバーは `true` だけを有効にする
- ルート画面に「このルートの坂と日陰」を出す。地図に描いた寄り道・最短ルートを、事前計算グリッド（上野〜谷中、`public/terrain/`）で集計する。標高で評価できた割合が 80% 未満のルートは値を出さず「対象外」とする（`docs/ARCHITECTURE-POLICY.md` の「必要なデータが欠ける候補は出さない」に合わせた）
- 日陰は午前10時の値を代表に出す。時間帯ごとの値は `/terrain` で見る
- 画面の並びを「知らせ → クエスト → 坂と日陰 → /terrain への導線」にし、地図に重ねていたクエストカードをやめて余白（gap-5・px-4）を取った

## 捨てた案

- Maps Elevation API: どの行き先でも坂を出せるが、新しい有料 API の有効化が要る（要相談）。日陰は出せない
- 表示のアピールだけ: 「坂を減らしたい」に応えられない

## 未検証

- ブラウザでの見た目（この作業ではブラウザに接続できなかった）。stg で確認する
- 出発地は現在地なので、上野〜谷中の外から使うと「対象外」になる。デモは範囲内の出発地で行う必要がある
