## 判断した内容と理由

### 1. AI 利用材料のファイル名を `docs/AI_USAGE.md` にした

- 候補A（採用）: `docs/AI_USAGE.md`。`docs/HACKATHON.md` の転記元チーム方針に同じ名前があり、必須記入の元データとして一致する
- 候補B: `docs/DEMO.md` に節として入れる。ファイルは増えないが、提出材料とデモ手順が混ざる
- 内容は「プロダクト内の AI（Gemini のクエスト生成、使わない場面）」と「開発の AI（コーディングエージェント・superloop）」に分けた。事実のみで、所感（「得たこと・成長したこと」）は PM の記入欄として残した

### 2. `docs/STATUS.md` は追記ではなく全面書き換えにした

- 旧版は 2026-11-06 時点の観測（「プロダクトの UI は main にない」「テスト基盤なし」）で、現在と大きく違う。追記すると新旧が混在して読み違えるため、同じ構成（観測事実・必須項目の対応表・不足）で現在のコードに合わせて書き直した
- 候補として「旧版を残して追記」もあったが、時系列メモは `git log` と `docs/decisions/` が担うので捨てた

### 3. `docs/DEMO.md` の構成

- 「5分デモの手順（時間配分つきの表）」「ローカル確認手順」「stg 確認手順」「デモ中の失敗時の対処表」の4部にした。失敗時に流れが止まらないことが評価基準（`docs/RULES.md`）なので、対処表を独立して置いた
- stg URL は `docs/environments.md` のデフォルトドメインを使い、実動確認済みの経緯は判断記録へのリンクに留めた（数値・引用の出典ルール）
