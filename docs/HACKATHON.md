## 大会必須ルール（転記）

### テーマ

**"Own the Why, Build with Intent."**

AI の提案をそのまま採用せず、人間が技術の Pros/Cons を比べて
「なぜそれを選んだか」を自分の言葉で語れることが求められている（転記）。
選んだ理由と捨てた案の記録が提出ドキュメントの材料になる。

### プロダクトのカテゴリ（必須）

次のいずれか1つに入ること。**カテゴリ外は審査対象外**（転記）。

医療・福祉 / 観光 / 教育 / エンターテインメント / クリエイティブ

### 実行基盤（必須）

アプリの実行に次のいずれか1つ以上を使うこと。**使っていなければ審査対象外**（転記）。

App Engine / Compute Engine / GKE / Cloud Run / Firebase App Hosting / Firebase Hosting

### 技術・表現のルール

- プロダクトのメイン技術スタックは Google 技術にする
- 開発での AI コーディング支援ツールの利用は可
- デモ・ピッチで他社製品を前面に出さない。他社 AI ツールが前面に出ているものは審査対象外
- API キーや秘密情報をリポジトリにコミットしない（審査項目「安全性」に関わる）
- GDG のコミュニティガイドラインを守る

### 開発開始前（11/5 10:00 より前）の禁止事項（転記）

- 禁止: プロダクトのソースコード、IaC（Terraform 等）、CI/CD、フレームワーク初期化（ボイラープレート生成）
- 許可: 開発環境の整備、技術検証のための PoC、デザインツールでの UI デザイン
- **PoC のコードを本番リポジトリへコピー・流用するのも禁止。違反は失格になり得る**

### 審査基準（8項目 × 0〜3点 = 24点、転記）

1. Google 技術の活用
   - a. Google 技術がプロダクトの中核で有効に機能しているか
   - b. 採用理由が合理的かつ具体的に説明されているか
2. プロダクトの完成度
   - a. 課題解決に必要な操作が一連の流れとして動くか
   - b. 対象ユーザーが目的を達成できる UI・UX か
   - c. 安全性・拡張性・保守性を意識した設計か
3. 社会課題への解決力
   - a. 解決する課題が具体的かつ明確か
   - b. 機能・仕組みが実際の課題解決に有効か
4. ピッチの構成と説明力
   - a. デモ・話の構成が分かりやすくインパクトがあるか

採点外だが必須記入（転記）: AI をどの場面でどう使ったか・なぜその場面か / 開発を通して得たこと・成長したこと

## 元チームの方針（転記。公式必須ではない）

転記元リポジトリのチームがとっていた方針。**このPJがそのまま採用するとは限らず、採否は PM が判断する。**
根拠となっている提出要件（著作物利用シート、AI 利用の記入など）は上記「必須」側に残ることに注意。

- LLM は Gemini を使う（「Google 技術の活用」の評価対象にするための判断。他社 LLM API の内部利用自体は転記上も禁止されていない）
- Gemini は Vertex AI 経由で呼ぶ（Google Cloud クレジットが Google AI Studio に適用されない、という転記元の判断）
- 技術を選ぶたびに `DECISIONS.md` に候補・メリット/デメリット・捨てた理由を記録する（テーマ "Own the Why" と審査項目 1-b の材料）
- 素材・ライブラリ・データの出典とライセンスを `ASSETS.md` に記録する（著作物利用シートの元データ）
- AI の使用箇所と理由を `AI_USAGE.md` に記録する（必須記入の元データ）
- デプロイは最小構成にする（チーム $20 クレジットの節約。転記元の例: Cloud Run `--max-instances 1`）
